Agent Graph — agents/graph.py

Every task is one TaskState dict threaded through a LangGraph state machine — no agent calls another directly. QA mode (default) runs the top loop once. Report mode (DS-STAR+) runs that same loop once per sub-question, then drafts and self-critiques a combined report below. Every node checks for stop/pause before it runs. Loop-back paths run through the margin lanes on the left and right — follow a line's color, not just its position, where paths cross.

LLM routing llm_router.py

Every call goes through OpenRouter. Each agent is pinned to a quality tier; a live DB toggle (app_settings.llm_speed_profile) swaps the whole tier→model map between free and fast-paid, no restart.

TierAgents
highplanner, coder, verifier, debugger, question_generator

writerisolated tier — small fast-paid models default to terse prose, breaking the report's depth requirement

Sandbox isolation

  • network: none — generated code cannot reach the internet or the backend
  • mount: data/ read-only; script written to a bind-mounted tempdir
  • memory: 2GB cap per container, discarded after each run
  • user: non-root inside python:3.12-slim
  • socket: backend never touches docker.sock directly — only via docker-socket-proxy, which allow-lists container/image create-start-kill-wait and hard-blocks EXEC, VOLUMES, SECRETS, SWARM, BUILD

Persistence & auth

  • checkpointing: AsyncPostgresSaver keyed by task_id — an in-flight task survives a backend restart
  • cooperative control: stop/pause/resume checked at every node boundary; an in-flight sandbox run is force-killed, never waited out
  • auth: Supabase JWT bearer token on every /api/v1/* call, per-user row-level security
  • concurrency: capped at MAX_CONCURRENT_PIPELINES (10) — above that, submissions still 202 and queue
  • tables: tasks, app_settings, domain_pack_configs, domain_pack_documents, domain_pack_chunks (vector + tsvector, RAG)

Domain packs

A pack biases the whole pipeline's persona, classification, and sub-question dimensions toward a domain — e.g. fraud_aml_example.py — and grounds answers in uploaded reference documents via a per-pack RAG knowledge base.

  • catalog.py — lists available packs
  • domain_pack.py — reads the active pack from Supabase app_settings, fail-closed to generic
  • knowledge.py — ingests uploaded docs into the pack's vector KB
  • domain_knowledge.py — RAG retrieval shared by planner / coder / verifier
  • switching a pack takes effect immediately — no restart

Frontend shell

Routing & state App.jsx

  • / → EmptyState — query box, QA/report toggle, submit
  • /task/:taskId → Dashboard — polls GET /get_task/{id} every 2s while running (no websocket/SSE); ReportPanel switches between live-progress, review-gate, and completed views by task.status
  • /domain-packs → DomainPacks — browse/activate, upload KB docs
  • AppShell wraps every route with the persistent sidebar / mobile drawer and its own error boundary
  • every task gets its own URL — refresh, back/forward, and copy-paste links all land back on the same report

Shared context

  • useAuth — Supabase session state; api.js's axios interceptor attaches the JWT to every request
  • useDrawer — lets any page open AppShell's single mobile drawer without owning a <Sheet> itself
  • useTaskList — lets a just-submitted task appear in the sidebar instantly, instead of waiting on its own 5s poll
  • useActiveDomainPack / useHealth — active pack + backend health, polled independently
